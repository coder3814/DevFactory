# DevFactory scripts

Run as `python <plugin>/scripts/devfactory.py <command> ...` (Python 3, standard library only; `python` on Windows, and the shebang `#!/usr/bin/env python3` elsewhere). Input files may use CRLF or LF line endings. Exit 0 is success, 1 a failed check with findings on stdout as `<code> <message>`, 2 a usage or environment error on stderr. Tests, from the repository root: `python -m unittest discover -s devfactory/scripts/tests -t .` for this script and `python -m unittest discover -s devfactory/hooks/tests -t .` for the hooks.

- `stamp --card <n> [--repo owner/name]` or `stamp --text <file>`: prints the card revision (SHA-256 of title, LF, body without spec lines, LF line endings, no trailing LFs); `--text` takes the first line as title. Exit 0, 2 when `gh` or the file fails.
- `stamp-check --card <n> [--repo owner/name] --spec <dir>` (or `--text <file>` for the card): prints `match` or `changed <old> <new>`, then `ancestor` or `not-ancestor` for the stamped Repo commit against HEAD in cwd. Exit 0 on match and ancestor, 1 otherwise, 2 when the stamp rows, `gh` or `git` fail.
- `spec-lint <dir> [--criteria <file>]`: checks `spec.md`: every header row present, and non-empty except that a drafting spec may leave Card revision, Repo commit and Stamped empty; Status one of drafting, Ready, approved; each Request type one of feature, bug fix, refactor, data correction, other; when Ready or approved, a Card revision of 64 lowercase hex, a Repo commit of 7 to 40 hex and a Stamped date of the form YYYY-MM-DD; the required sections in order; a Dispositions row for each core concern (Existing data changed, Security, Performance, Release sequencing, Owner steps) and no blank Disposition cell, where a cell holding only an italic prompt (`*...*`) counts as blank; the Evidence plan's six columns and a row per criterion ID given (one per line) and none for an unknown ID; a Moment on every owner step; a row in the Amendments table; and that `gaps.md` parses. Exit 0 clean, 1 findings, 2 no `spec.md`.
- `criteria-ids --card <n> [--repo owner/name]` or `--text <file>`: prints each criterion ID opening a list item (under "Acceptance criteria" when the card has that heading), then `duplicate <ID>` for any repeated one. Exit 0, 1 on a duplicate.
- `gaps add <dir> --stage <Approval|Development|Done|Acceptance> --question <q> --condition <c> [--resolved <v>]`: appends a dated entry to `<dir>/gaps.md`; Resolved by defaults to `open`. Exit 0, 2 on a bad stage or folder.
- `gaps check <dir>`: reports `gap-open` for each entry resolved by `open` and `gaps-parse` for a malformed file. Exit 0 / 1.
- `gaps ledger <dir> --card <n> --types <t> --ledger <file>`: appends every entry to the ledger under `## <card> (<types>) — <date> — <stage>` and prints `appended <count>`. Exit 0, 1 when `gaps.md` does not parse.
- `evidence-check <dir> --criteria <file>`: checks each `evidence/<ID>/` exists, is non-empty, and every artifact has a one-line `<name>.txt` sidecar with `revision:`, `checkpoint:` and `produced by:`. Inside a git work tree it also reports `evidence-uncommitted` for a file in those folders that is not committed at HEAD (untracked or ignored) or differs from its committed version, `sidecar-revision` for a revision that is not a commit, or neither an ancestor of HEAD nor a commit whose change a rebase carried into HEAD unaltered (`git cherry` finds its patch there), and, when `spec.md` has an Evidence plan, `sidecar-checkpoint` for a checkpoint none of the criterion's rows names (compared without regard to case, backticks or bold). Exit 0 / 1.
- `receipt write <dir> --check request (--card <n> [--repo owner/name] | --text <file>) --facts <file>` or `receipt write <dir> --check ready --specs <file>`: writes or replaces that check's receipt in `<dir>/receipts.md` with the fingerprint `spec-template.md` defines under `receipts.md`, creating `<dir>` if needed; prints `wrote <check> <file>`. `receipt check` with the same arguments prints `match <check>`, `no-receipt <check>`, or `differs <field> <old> <new>` for each field that changed; the Repo commit differs when it is not an ancestor of HEAD or anything outside the profile's specs path and `.devfactory/` changed since it. Exit 0 on write or match, 1 otherwise, 2 on bad arguments or a missing spec folder.
- `begin <skill>` / `end <skill>`: writes (or refreshes) or removes `<root>/.devfactory/.active/<skill>` holding an ISO timestamp; `begin` prints `active <other> since <time> (<age> ago)` or `stale <other> ...` for each other marker and `refreshed <skill>` when its own existed. Exit 0.
- `markers [--clear-stale]`: lists each marker as `active` or `stale` with its time and age; a marker is stale when older than the profile's `- Marker lifetime: <hours>h` under Hooks (default 12h), and the guards ignore it. `--clear-stale` removes the stale ones and prints `cleared <skill>`. Exit 0.
- `profile [--section <heading>] [--field <name>]`: prints `<root>/.devfactory/profile.md`, the named section's lines (its subsections included, its heading not), or one field's value, within the section when given. A field line is `- Name: value`, `* Name: value`, `- **Name:** value` or `- **Name**: value`; the name matches without regard to case. This is the one profile parser; the hooks call it. Exit 0, 2 when the profile, section or field is missing.

- `event <name> --card <id>`: fires one of the events `request-met`, `ready`, `approved`, `work-started`, `development-started`, `readiness-lost`, `done`, `refused`, `accepted`, `released`. Runs the project's hook for it, the one file in `<root>/.devfactory/hooks/` whose name without extension is the event, matched without regard to case (`.py` with this Python, `.ps1` with PowerShell, `.cmd` or `.bat` with cmd, `.sh` or no extension with bash, never the Windows System32 launcher), from `<root>`, with the card ID as its argument and `DEVFACTORY_EVENT` and `DEVFACTORY_CARD` set, for at most 300 seconds. Prints the hook's output then `ran <file>`, or `no-hook <name>` when there is none. Exit 0, 1 when the hook fails, times out (its process tree is killed) or has no runner for its type (`hook-failed <file> ...`), 2 on an unknown event, no card or two hooks for one event.

`<root>` is the repository root of the current directory (`git rev-parse --show-toplevel`, a worktree's own root), or the current directory outside a repository.
