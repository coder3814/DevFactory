# DevFactory scripts

Run as `python <plugin>/scripts/devfactory.py <command> ...` (Python 3, standard library only; `python` on Windows, and the shebang `#!/usr/bin/env python3` elsewhere). Input files may use CRLF or LF line endings. Exit 0 is success, 1 a failed check with findings on stdout as `<code> <message>`, 2 a usage or environment error on stderr. Tests, from the repository root: `python -m unittest discover -s devfactory/scripts/tests -t .` for this script and `python -m unittest discover -s devfactory/hooks/tests -t .` for the hooks.

Every command takes only the flags listed for it here; any other flag is a usage error, `devfactory: unknown flag --<x> for <command>` (the command with its subcommand where it has one), exit 2. `devfactory` alone, `devfactory help`, `devfactory --help`, `devfactory -h` and `devfactory <command> --help` (or `-h`) print the commands and their flags and exit 0. `--clear-stale` and `--post-release` take no value; every other flag takes one, as `--name value` or `--name=value`.

- `stamp --card <n> [--repo owner/name]` or `stamp --text <file>`: prints the card revision (SHA-256 of title, LF, body without spec lines, LF line endings, no trailing LFs); `--text` takes the first line as title. Exit 0, 2 when `gh` or the file fails.
- `stamp-check --card <n> [--repo owner/name] --spec <dir>` (or `--text <file>` for the card): prints `match` or `changed <old> <new>`, then `ancestor` or `not-ancestor` for the stamped Repo commit against HEAD in cwd. Exit 0 on match and ancestor, 1 otherwise, 2 when the stamp rows, `gh` or `git` fail.
- `spec-lint <dir> [--criteria <file>]`: checks `spec.md`: every header row present, and non-empty except that a drafting spec may leave Card revision, Repo commit and Stamped empty; Status one of drafting, Ready, approved; each Request type one of feature, bug fix, refactor, data correction, other; when Ready or approved, a Card revision of 64 lowercase hex, a Repo commit of 7 to 40 hex and a Stamped date of the form YYYY-MM-DD; the required sections in order; a Dispositions row for each core concern (Existing data changed, Security, Performance, Release sequencing, Owner steps) and no blank Disposition cell, where a cell holding only an italic prompt (`*...*`) counts as blank; the Evidence plan's six columns and a row per criterion ID given (one per line) and none for an unknown ID; a Moment on every owner step; a row in the Amendments table; and that `gaps.md` parses. Other files in the folder are not read. Exit 0 clean, 1 findings, 2 no `spec.md`.
- `criteria-ids --card <n> [--repo owner/name]` or `--text <file>`: prints each criterion ID opening a list item (under "Acceptance criteria" when the card has that heading), then `duplicate <ID>` for any repeated one. Exit 0, 1 on a duplicate.
- `gaps add <dir> --stage <Approval|Development|Done|Acceptance|Release> --question <q> --condition <c> [--resolved <v>] [--kind miss|request-change]`: appends a dated entry to `<dir>/gaps.md` with the fields Question or refusal, Let through by, Kind and Resolved by. `--condition` is exactly one condition written `Ready <id>` or `Done <id>`, where `<id>` (such as `3.2`) is a condition numbered under "Conditions" in `references/definition-of-ready.md` or `references/definition-of-done.md`, read when the command runs; anything else is a usage error that shows the form. Kind defaults to `miss`; Resolved by defaults to `open`. Exit 0, 2 on a bad stage, condition, kind or folder.
- `gaps check <dir>`: reports `gap-open` for each entry resolved by `open` and `gaps-parse` for a malformed file. An entry without a Kind, or whose Let through by is not in the `Ready <id>` or `Done <id>` form, still parses. Exit 0 / 1.
- `gaps ledger <dir> --card <n> --types <t> --ledger <file>`: appends each entry to the ledger under `## <card> (<types>) — <date> — <stage>`, skipping an entry the ledger already holds for that card (the same date, stage and question; the card matches with or without a leading `#`), and prints `appended <a> skipped <b>`. Exit 0, 1 when `gaps.md` does not parse.
- `evidence-check <dir> --criteria <file> [--base <rev>] [--post-release]`: checks each `evidence/<ID>/` exists, is non-empty, and every artifact has a one-line `<name>.txt` sidecar with `revision:`, `checkpoint:` and `produced by:`. Inside a git work tree it also reports `evidence-uncommitted` for a file in those folders that is not committed at HEAD (untracked or ignored) or differs from its committed version, `sidecar-revision` for a revision that is not a commit, or neither an ancestor of HEAD nor a commit whose change a rebase carried into HEAD unaltered (`git cherry` finds its patch there), and, when `spec.md` has an Evidence plan, `sidecar-checkpoint` for a checkpoint none of the criterion's rows names (compared without regard to case, backticks or bold). With `--base`, it also reports `evidence-stale` for a sidecar revision at which any code file the change set touches (`git diff --name-only <base>...HEAD`) differs from HEAD, naming up to three of them; code is everything outside the spec folder, the profile's specs path, `.devfactory/` and the comma-separated paths of the profile's Specs `Not code` field, and a revision that is the base or an ancestor of it is not tested. A criterion every evidence-plan row of which has "(post-release)" after its checkpoint, and that has no artifact yet, is reported `evidence-pending`, which is not a finding; `--post-release` treats those rows as due, for checking a release's capture in `.devfactory/post-release/<card>/`, whose `plan.md` stands in for `spec.md`. A sidecar's checkpoint is compared without the marker. Only the `evidence/<ID>/` folders are read, so the records files are not. Exit 0 / 1 (pending lines alone exit 0), 2 when `--base` is not a commit.
- `spec-only <dir> --base <rev>`: prints `spec-only` when every path that differs between `<rev>` and HEAD (`git diff --name-only <rev> HEAD`) is inside the spec folder `<dir>`; otherwise prints `outside <path>` for each path outside it, repository-relative and sorted. Exit 0 / 1, 2 when `<dir>` is not a folder below the root of a git work tree or `--base` is not a commit.
- Review records are kept outside the tracked tree, in the store `<git common dir>/devfactory/reviews/<card id>.md`, where the git common dir is `git rev-parse --git-common-dir` run from `<root>` and made absolute, so every worktree of a repository reads and writes the same store, and nothing in it is tracked or committed. The card id is given with or without a leading `#` and names the file without it. The `reviews` commands take no folder argument; outside a git repository, or for a card id that cannot name a file, they are a usage error.
- `reviews add --card <id> --round <n> --verdict <PASS|FAIL|DONE|NOT DONE> [--findings <file>]`: appends to the card's store file, creating its folder when first written, a block `## <date> — round <n> — <verdict>` followed by one `- <Done id> | <criterion ID or -> | <text>` line per non-blank line of the findings file. Each findings line is written `Done <id> | <criterion ID or -> | <text>` (a leading `- ` is allowed), where `Done <id>` is validated as `gaps add` validates a Done condition and the criterion ID is `C<n>` or `-`. `--round` is a whole number from 1. Exit 0, 2 on a bad card, round, verdict or findings line.
- `reviews show --card <id>`: prints the card's stored record, or `no-reviews` when it has none. Exit 0.
- `reviews ledger --card <id> --ledger <file>`: files each block of the card's stored record in the ledger as `### <date> — round <n> — <verdict>` with its finding lines, under the card's `## <card>` heading (added at the end of the ledger when it has none; the card matches with or without a leading `#`), skipping a block whose heading is already under it, prints `appended <a> skipped <b>`, and then removes the card's store file. With no store file it prints `appended 0 skipped 0`. Exit 0, 1 (`reviews-parse ...`) when the stored record does not parse, which leaves the store file in place.
- `receipt write <dir> --check request (--card <n> [--repo owner/name] | --text <file>) --facts <file>` or `receipt write <dir> --check ready --specs <file> --commit <rev> [--parent <id> [--repo owner/name] | --parent-text <file>]`: writes or replaces that check's receipt in `<dir>/receipts.md` with the fingerprint `spec-template.md` defines under `receipts.md`, creating `<dir>` if needed; prints `wrote <check> <file>`. The Standard field is a hash of the plugin's `references/` and `agents/` alone. For the ready check, `--commit` is required: it is the commit the checker reported reading, must name a commit in the repository (`git rev-parse --verify <rev>^{commit}`) and is recorded as the Repo commit by its full hash. `--parent <id>` (read with `gh`) or `--parent-text <file>` (first line the title) also records the parent card's revision as Parent card. The Specs content leaves out `receipts.md`. `receipt check` takes the same arguments without `--commit` and prints `match <check>`, `no-receipt <check>`, or `differs <field> <old> <new>` for each field that changed: the Repo commit differs when it is not an ancestor of HEAD or anything outside the profile's specs path and `.devfactory/` changed since it; a stored Standard of the form `<version> <hash>` matches when its hash matches; sub-issue lines in the facts file compare as a set, like every other fact line; and Parent card is compared when the receipt records one, which then needs `--parent` or `--parent-text`. Exit 0 on write or match, 1 otherwise, 2 on bad arguments, a missing spec folder or a `--commit` that is not a commit.
- `begin <skill>` / `end <skill>`: writes (or refreshes) or removes `<root>/.devfactory/.active/<skill>`, which holds an ISO timestamp and, on a second line, `plugin <version>`. Any skill name of letters, digits, `.`, `_` and `-` is taken, `start` and `curate` among them. `begin` prints `active <other> since <time> (<age> ago)` or `stale <other> ...` for each other marker and `refreshed <skill>` when its own existed, then `began <skill> <plugin version>`, then `plugin-changed <old> <new>` when the marker it refreshed was written under another plugin version (`unknown` for a marker that records none). The plugin version is the `version` in `.claude-plugin/plugin.json`. Exit 0.
- `markers [--clear-stale]`: lists each marker as `active` or `stale` with its time and age; a marker is stale when older than the profile's `- Marker lifetime: <hours>h` under Hooks (default 12h), and the guards ignore it. `--clear-stale` removes the stale ones and prints `cleared <skill>`. Exit 0.
- `profile [--section <heading>] [--field <name>] [--rev <ref>]`: prints `<root>/.devfactory/profile.md`, the named section's lines (its subsections included, its heading not), or one field's value, within the section when given. With `--rev`, it reads the profile at that revision (`git show <ref>:.devfactory/profile.md`) instead of the working tree. A field line is `- Name: value`, `* Name: value`, `- **Name:** value` or `- **Name**: value`; the name matches without regard to case. This is the one profile parser; the hooks call it. Exit 0, 2 when the profile, section, field or revision is missing.
- `event <name> --card <id>`: fires one of the events `request-met`, `ready`, `approved`, `work-started`, `development-started`, `readiness-lost`, `done`, `refused`, `accepted`, `released`. Runs the project's hook for it, the one file in `<root>/.devfactory/hooks/` whose name without extension is the event, matched without regard to case (`.py` with this Python, `.ps1` with PowerShell, `.cmd` or `.bat` with cmd, `.sh` or no extension with bash, never the Windows System32 launcher), from `<root>`, with the card ID as its argument and `DEVFACTORY_EVENT` and `DEVFACTORY_CARD` set, for at most 300 seconds. Prints the hook's output then `ran <file>`, or `no-hook <name>` when there is none. Exit 0, 1 when the hook fails, times out (its process tree is killed) or has no runner for its type (`hook-failed <file> ...`), 2 on an unknown event, no card or two hooks for one event.

`<root>` is the repository root of the current directory (`git rev-parse --show-toplevel`, a worktree's own root), or the current directory outside a repository.
